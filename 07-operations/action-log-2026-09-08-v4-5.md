# Action Log — Bao Rescue v4.5

Date: 2026-09-08

## Trigger
User reported that the live website images were blurry and some visual mappings were wrong.

## Root cause
The deployed v3 JPG assets were only about 4–5 KB each. They were thumbnails being enlarged by the browser. In addition, the old UI reused some assets for more than one semantic state (for example, collapsed imagery was also used as an over-proof proxy), and the dense branch did not use a proper cut-open crumb comparison.

## v4.5 changes
1. Replace tiny JPG thumbnails with 1200×900 high-quality WebP reference photos.
2. Separate visual assets by meaning: normal, under-proofed, over-proofed, collapsed, wrinkled, wet/pitted, fluffy crumb, dense crumb, gummy crumb.
3. Remove `Cracked` from the core first-screen symptom grid because it is style-dependent and the branch is still beta; move it under Other/Special cases.
4. Add a first-screen `Didn't rise / stayed small` symptom, which is better supported by the current diagnosis logic.
5. Add a cut-open `fluffy / dense / gummy` comparison to the Dense path.
6. Stop reusing the collapsed photo as the over-proof reference.
7. Update Pages staging to publish the v4 WebP asset directory instead of the old v3 JPG thumbnails.

## Commercial QA rule added
Any diagnostic image must pass both:
- pixel-quality gate: at least 1200×900 source for large cards / hero use;
- semantic gate: the image must depict the observable state named by the card and cannot be reused to stand in for a different cause/state.
