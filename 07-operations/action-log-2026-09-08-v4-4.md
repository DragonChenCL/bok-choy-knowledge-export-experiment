# Action Log — Bao Rescue v4.4

Date: 2026-09-08

## Goal
Continue improving the live Bao Rescue product while preserving the rule that the deployed root always reflects the latest diagnosis source.

## Evidence check
Before changing the proofing UI, current steamed-bun guidance was re-checked. Repeated practical cues were consistent: ready buns are roughly 50% puffier, feel lighter, and a finger indent returns slowly; a fast rebound points to under-proofing; no recovery points to over-proofing.

## Product changes
1. Added a real product hero above the diagnosis flow.
2. Added a direct `Start free diagnosis` CTA into the live tool.
3. Added product-positioning chips: photo first, cause ranking, one-variable test, evidence-aware.
4. Added a three-step explanation of how the diagnostic system works.
5. Strengthened proof-state cards with observable visual + tactile cues instead of photo labels alone.
6. Added an evidence note to proof-state questions and result pages.
7. Kept uncertain branches labeled `BETA`, `NEEDS MORE INFO`, or `CONFLICTED EVIDENCE` rather than forcing certainty.

## CI changes
The Pages workflow no longer verifies one hard-coded version string such as `v4.3`. It now checks invariant product markers (`Why did my bao fail?`), the exact build SHA, and the injected deployed-commit marker. This prevents routine version bumps from breaking deployment while retaining freshness checks.

## Source-of-truth rule
`site/diagnose/index.html` remains the only live product source. Every build promotes that exact file to both `/` and `/diagnose/`.

## Status
v4.4 candidate ready for automatic deployment and live review.
